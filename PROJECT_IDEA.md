1. Проблема
Telegram-проект продвигается через закупку рекламы и разные источники трафика (посевы в каналах, YouTube-видео, контекстная реклама, таргет). Трафик ведётся в бесплатный канал по персональным именованным invite-ссылкам — поэтому источник подписки известен.

Но дальше воронка обрывается: подписчик покупает доступ в платный закрытый чат, и связь с источником теряется. В результате:

Невозможно понять, какой источник приносит платящих клиентов, а не просто подписчиков.
Расходы по источникам считаются вручную в таблицах, метрики (CAC, ROMI, окупаемость) сводятся «на глаз» раз в неделю.
Бюджет распределяется вслепую: источник с дешёвым подписчиком может давать дорогого клиента — и наоборот.
Цена ошибки: при бюджете 100 000–500 000 ₽/мес на трафик 20–40% сливается в источники с нулевой окупаемостью, потому что их вклад в продажи невидим.

2. Решение
Telegram-бот (админ в бесплатном канале и платном чате) + сквозная аналитика по user_id:

Создаёт/импортирует именованные invite-ссылки под каждый источник трафика.
Ловит вступления в бесплатный канал (chat_member) → записывает user_id → источник → дата в БД.
Ловит вступления в платный чат (chat_member) → находит user_id в БД → проставляет факт покупки и связывает с источником.
Считает метрики по каждому источнику: подписчики, клиенты, конверсия, CPF, CAC, выручка, ROMI, окупаемость.
Синхронизирует данные в Google Sheets (двусторонне: расходы и цена продукта вводятся в таблице, метрики бот пишет обратно).
Показывает дашборд владельцу: команды бота /stats, /sources, веб-страница с таблицей по источникам.
Каждый шаг = отдельный модуль спецификации.

3. Почему сейчас
Telegram Bot API стабильно отдаёт апдейты chat_member с объектом invite_link (с именем ссылки) — связка источника технически надёжна.
Telegram-инфобизнес и платные сообщества — растущая ниша в СНГ; рекламные бюджеты выросли, а инструментов сквозной аналитики «подписка → продажа» под Telegram почти нет.
Готовые трекеры (например, для веб) не понимают Telegram-воронку «канал → чат» по user_id.
4. Целевая аудитория
Основная: владельцы Telegram-проектов с платным закрытым чатом/каналом, закупающие трафик из 3+ источников. Задача: понять окупаемость каждого источника. Сейчас используют: ручные Google-таблицы, UTM-метки в ссылках без связки с продажей.

Вторичная: трафик-менеджеры и агентства, ведущие несколько Telegram-проектов. Задача: отчётность перед клиентом по ROMI каждого источника. Сейчас используют: скриншоты статистики канала + Excel.

7. Конкуренты
Конкурент	Что делает	Чего не хватает
Ручная Google-таблица	Учёт расходов и подписчиков вручную	Нет связки подписка→продажа по user_id, всё руками
TGStat / Telemetr	Аналитика каналов, охваты	Не видит платный чат и продажи, нет ROMI по источнику
UTM-трекеры (web)	UTM-метки, конверсии на сайте	Не работают внутри Telegram-воронки канал→чат
Боты-«геткурсы»	Приём оплат, выдача доступа	Не связывают оплату с источником подписки на канал
8. План запуска
MVP (фаза 1, 2–3 недели):

Бот-админ ловит chat_member в бесплатном канале → пишет источник по invite_link.name.
Бот-админ ловит chat_member в платном чате → связывает по user_id.
Команды /sources, /newsource, /stats.
Хранение в Supabase, ручной ввод расхода командой /cost.
Метрики: подписчики, клиенты, конверсия, CAC, ROMI.
Фаза 2 (v2):

Google Sheets двусторонняя синхронизация (расход и цена продукта из таблицы).
Cron-пересчёт метрик (APScheduler).
Веб-дашборд (FastAPI).
Фаза 3 (v3):

Мультипроект, тарифы, приём оплаты, экспорт CSV, API.
Метрики успеха MVP: доля «источник определён» среди новых клиентов ≥ 90%; время от вступления в платный чат до записи в БД ≤ 5 сек.

9. Риски
Риск	Вероятность	Митигация
Источник вступления нельзя получить задним числом	Высокая	Бот ставится админом и слушает события до запуска трафика; строка «Источник не определён» как fallback
Пользователь вышел и зашёл заново — другая/нет ссылки	Средняя	Хранить первую атрибуцию по user_id (первое событие join); поле attribution_locked
chat_member не приходит (не включён allowed_updates)	Средняя	Явно задать allowed_updates=["chat_member","message","callback_query","chat_join_request"]; health-check
Бот теряет права админа	Низкая	Периодическая проверка getChatMember(self); алерт владельцу
Превышение rate-limit Google Sheets	Средняя	Батч-запись раз в N минут, экспоненциальный backoff
Покупатель попал в чат без оплаты (ручное добавление)	Низкая	Флаг is_paid ставится только по правилу источника входа; ручные добавления помечаются manual
